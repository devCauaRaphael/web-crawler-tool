# Web Crawling

## Basic Web Crawler

This project contains a basic web crawling tool developed in Python. The crawler was built to practice web reconnaissance, HTTP requests, HTML parsing, URL discovery, and automated navigation through web pages.

The tool starts from a target URL, retrieves its HTML content, extracts HTTP/HTTPS links from the page, and recursively follows discovered URLs while keeping track of already crawled pages.

The project is intended as an educational implementation of the fundamental concepts behind web crawling tools used during information gathering and security assessments.

---

## How Does Web Crawling Work?

Web crawling is the process of automatically visiting web pages and extracting information from them.

A crawler generally follows this process:

1. Start with a target URL.
2. Send an HTTP request to the target.
3. Retrieve the HTML response.
4. Parse the HTML content.
5. Extract links from `<a>` tags.
6. Add undiscovered URLs to the crawling queue.
7. Visit the discovered URLs.
8. Keep track of previously crawled URLs to avoid processing the same page multiple times.

This tool implements this basic workflow using Python's `requests` and `BeautifulSoup` libraries.

## Features

### URL Crawling

The crawler receives a target URL through a command-line argument and uses it as the starting point of the crawling process.

```bash
python web_crawler.py https://example.com
```

The target URL is added to the crawling queue and processed automatically.

---

### HTTP Requests

The tool uses the `requests` library to retrieve the HTML content of each discovered URL.

A custom `User-Agent` header is included in the request to identify the client as a Firefox browser running on Linux.

```python
header = {
    "User-Agent": "Mozilla/5.0 (X11; Linux x86_64; rv:140.0) Gecko/20100101 Firefox/140.0"
}
```

This allows the crawler to send requests that resemble those generated by a standard web browser.

---

### HTML Parsing

After receiving the response, the crawler uses **BeautifulSoup** to parse the HTML document.

It searches for `<a>` elements containing an `href` attribute:

```python
tags_a = soup.find_all("a", href=True)
```

The extracted URLs are then processed by the crawler.

---

### Link Discovery

The crawler identifies HTTP links found inside the target page.

For example:

```html
<a href="https://example.com/about">About</a>
<a href="https://example.com/contact">Contact</a>
```

These URLs are extracted and added to the crawling queue if they have not been visited previously.

Currently, the crawler focuses on absolute URLs beginning with `http`.

---

### Duplicate URL Prevention

The crawler uses two data structures to manage URLs:

* `TO_CRAWL` — contains URLs waiting to be crawled.
* `CRAWLED` — contains URLs that have already been processed.

Before adding a discovered URL to the queue, the crawler checks whether it already exists in either collection.

This prevents the crawler from repeatedly processing the same URL.

---

### Crawling Queue

The crawler uses `TO_CRAWL` as a queue of URLs that still need to be processed.

When a URL is selected, it is removed from the collection:

```python
url = TO_CRAWL.pop()
```

The crawler then requests the page, extracts its links, and adds new URLs to the queue.

The process continues until there are no URLs left to crawl.

## Crawling Workflow

The current implementation follows this workflow:

```text
             Target URL
                  |
                  v
          Send HTTP Request
                  |
                  v
            Get HTML
                  |
                  v
          Parse HTML with
          BeautifulSoup
                  |
                  v
          Extract <a href>
                  |
                  v
       Check discovered URLs
                  |
          +-------+-------+
          |               |
      Already seen      New URL
          |               |
          |               v
          |         Add to queue
          |               |
          +-------+-------+
                  |
                  v
          Crawl next URL
                  |
                  v
          Queue empty?
             /       \
           No         Yes
           |           |
           v           v
        Continue      End
```

## Security Reconnaissance

Web crawling can be useful during the information-gathering phase of a security assessment.

By automatically discovering pages and links, a crawler can help identify parts of a web application that may not be immediately visible from the main page.

For example, crawling can help discover:

* Additional application pages
* Administrative interfaces
* Authentication pages
* Documentation pages
* Internal navigation paths
* Additional application endpoints

This makes web crawling a useful technique for mapping the potential attack surface of a web application.

## Current Limitations

The current implementation is intentionally simple and focuses on the fundamentals of web crawling.

Some limitations include:

* Only absolute HTTP/HTTPS links are currently processed.
* No configurable crawling depth.
* No request timeout configuration.
* No HTTP status-code analysis.
* No robots.txt handling.
* No scope restriction.
* No JavaScript rendering.
* No API endpoint detection.
* No concurrent requests.
* Only one static `User-Agent` is currently used.
* No advanced URL normalization.

These limitations provide opportunities for future improvements.

## Header Rotation

Implement HTTP header rotation to allow the crawler to use different request headers during the crawling process.

Possible headers to rotate include:

* `User-Agent`
* `Accept`
* `Accept-Language`
* `Referer`

This feature could make the crawler more flexible when interacting with different web applications.

---

## Threading

Implement multithreaded crawling to allow multiple URLs to be requested concurrently.

Currently, URLs are processed sequentially. Threading could significantly improve crawling performance when dealing with larger websites.

```text
Current:

URL 1 → Request → Response
                     ↓
URL 2 → Request → Response
                     ↓
URL 3 → Request → Response


Future:

URL 1 → Request ──┐
URL 2 → Request ──┼→ Concurrent Processing
URL 3 → Request ──┘
```

---

## Scope

Implement a configurable crawling scope.

The crawler should be able to restrict crawling to a specific domain or set of allowed domains.

For example:

```text
Target:
example.com

Allowed:
example.com
www.example.com

Ignored:
external-site.com
another-domain.com
```

This would prevent the crawler from unnecessarily following links to external websites.

---

## Depth

Implement configurable crawling depth to control how far the crawler can navigate from the initial URL.

For example:

```text
Depth 0
└── example.com

Depth 1
└── example.com
    ├── /about
    ├── /contact
    └── /login

Depth 2
└── example.com
    ├── /about
    │   ├── /team
    │   └── /company
    ├── /contact
    └── /login
```

A configurable depth would allow users to control the amount of content processed and prevent unnecessarily deep crawling.
